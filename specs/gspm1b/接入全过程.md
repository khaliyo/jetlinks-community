# GSPM1B 智能插座接入 JetLinks 全过程总结

本文档记录智鸟科技 **GSPM1B** 在社区版 JetLinks 2.10 上从 0 到可用的完整接入过程，包括配置、透传脚本、Topic 约定、验证方法，以及接入过程中在 **本仓库** 做的必要补丁。操作步骤细节仍可参阅 [README.md](./README.md)。

---

## 1. 接入目标与结果

| 项目 | 说明 |
|------|------|
| 产品 ID | `gspm1b` |
| 设备 ID | 设备 MAC，如 `c82b96f821e2`（与 JSON 字段 `mac` 一致） |
| 消息协议 | JetLinks 官方协议（MQTT Broker 模式） |
| 透传 Topic | 上行 `/gspm1b/{deviceId}/up`，下行 `/gspm1b/{deviceId}/down` |
| 设备侧协议 | GSPM 私有 JSON（`type` / `messageId` / `commandName` 等） |

**已验证能力：**

- 设备上线（MQTT 连接 + 透传 Topic 上行）
- 属性上报入库（电流、功率、电压、电量等）
- 功能下发（通断电、定时上报、查询信息/统计、按键锁等）
- Topic 上为**纯 JSON 字节**（非 `messageType:DIRECT` 外壳、非 base64 包装）
- 整型字段如 `key` 输出为 `1` 而非 `1.0`

## 2. 整体架构

```
┌─────────────┐     MQTT JSON      ┌──────────────────────────────┐
│  GSPM1B 设备 │ ◄──────────────► │ JetLinks MQTT 网关 (1883)     │
│  MAC=设备ID  │  up / down 分 Topic   │ 官方协议 + 透传路由（上行 /up） │
└─────────────┘                    └──────────────┬───────────────┘
                                                  │
                    ┌─────────────────────────────▼─────────────────────────────┐
                    │ TransparentDeviceMessageConnector                        │
                    │   上行：原始 JSON → transparent-codec.js → 属性/事件/功能回复 │
                    │   下行：功能调用 → transparent-codec.js → 原始 JSON payload   │
                    └─────────────────────────────┬─────────────────────────────┘
                                                  │
                    ┌─────────────────────────────▼─────────────────────────────┐
                    │ 物模型 (metadata.json) + 存储策略 timescaledb-row          │
                    │ 规则引擎 / 告警 / 可视化 / 历史查询                          │
                    └───────────────────────────────────────────────────────────┘
```

**可选中间层：** 若设备无法改 Topic，可通过 EMQX 规则把原厂 Topic 桥接到 `/gspm1b/{mac}/up` 与 `/down`，见 [emqx-bridge.md](./emqx-bridge.md)。

## 4. 标准接入流程（推荐顺序）

### 4.1 准备 JetLinks 运行环境

1. 启动依赖：PostgreSQL、Redis、TimescaleDB（按项目 `docker-compose` 或自有部署）。
2. **编译并启动** 本仓库 `jetlinks-standalone`（若使用下文「社区版补丁」，必须用当前源码构建）。
3. 确认 MQTT 网络组件端口（如 `1883`）与设备/EMQX 可达。

### 4.2 创建产品与物模型

1. **设备管理 → 产品 → 新建**
   - 产品 ID：`gspm1b`（与 `metadata.json` 中 `id` 一致）
   - 消息协议：**JetLinks 官方协议**
2. **物模型**：导入 [metadata.json](./metadata.json) 全文。
3. **存储策略**：设为 `timescaledb-row`（或你环境支持的时序策略）。  
   - 勿使用 `none`，否则属性不入库、历史查询为空。
4. **激活/应用配置**：在产品详情执行「激活」或调用 `POST /device-product/gspm1b/deploy`，确保物模型注册并创建 `properties_gspm1b` 等存储表。

### 4.3 MQTT 网络与设备网关

1. 新建 **MQTT 服务** 网络组件（`0.0.0.0:1883`）。
2. 新建 **MQTT 服务网关**，绑定上述网络，协议选 **JetLinks 官方协议**。
3. 产品 **接入方式** 选择该网关。

### 4.4 配置透传编解码

社区版可能**没有**「数据解析」页签（官方协议 jar 未向 UI 注册 `transparentCodec` 特性），可用 API：

```bash
export JETLINKS_URL=http://127.0.0.1:8848
export JETLINKS_TOKEN=<登录 token>
export PRODUCT_ID=gspm1b

python3 -c "
import json, pathlib
script = pathlib.Path('specs/gspm1b/transparent-codec.js').read_text(encoding='utf-8')
print(json.dumps({
    'provider': 'jsr223',
    'configuration': {'lang': 'js', 'script': script}
}, ensure_ascii=False))
" > /tmp/gspm1b-codec.json

curl -X POST "$JETLINKS_URL/device/transparent-codec/$PRODUCT_ID" \
  -H 'Content-Type: application/json' \
  -H "X-Access-Token: $JETLINKS_TOKEN" \
  -d @/tmp/gspm1b-codec.json
```

验证：`GET /device/transparent-codec/gspm1b` 应返回完整脚本。

**脚本职责摘要：**

- **上行**：解析 GSPM JSON（`commandName`、`data` 等）→ `reportProperty` / `fireEvent`
- **下行**：`whenFunction` 映射为 GSPM 指令 JSON，经 `toDevicePayload()` 输出字符串，保证 `key` 等为整数格式
- **设备 ID**：优先 JSON `mac`，否则用 Topic 中的 `{deviceId}`

### 4.5 注册设备实例

| 字段 | 值 |
|------|-----|
| 设备 ID | MAC，如 `c82b96f821e2` |
| 产品 | `gspm1b` |
| MQTT clientId | 建议与设备 ID 相同 |

### 4.6 设备 MQTT / Topic（二选一）

**推荐：直接改设备 Topic**（见 [emqx-bridge.md 方案 C](./emqx-bridge.md)）

```
publish（设备→平台）: /gspm1b/{mac}/up
subscribe（平台→设备）: /gspm1b/{mac}/down
server: JetLinks MQTT 地址
port: 1883
```

**备选：** 设备保持原厂 Topic，用 EMQX 规则分别映射到 `/up` 与 `/down`，见 [emqx-bridge.md](./emqx-bridge.md)。

## 5. 协议与消息约定

### 5.1 JetLinks 透传 Topic

```
上行: /{productId}/{deviceId}/up
下行: /{productId}/{deviceId}/down
```

示例：上报 `/gspm1b/c82b96f821e2/up`，订阅 `/gspm1b/c82b96f821e2/down`

JetLinks 网关**只订阅** `/+/+/up`；平台下发 publish 到 `down`。官方编解码内部仍将 `/up` 规范为 `/direct` 段名，无需设备发 `/direct`。

### 5.2 下行（平台 → 设备）

功能调用后，MQTT Topic 上应为**原始 JSON**，例如通断电：

```json
{"type":"event","messageId":"1780222871550490","key":1}
```

| JetLinks 功能 | GSPM 下发要点 |
|---------------|---------------|
| `powerControl` | `type=event`，`key` 0/1 |
| `restart` | `type=setting`，`system=restart` |
| `setTimerReport` | `type=setting`，`timerEnable`、`timerInterval` |
| `queryInfo` | `type=info` |
| `queryStatistic` | `type=statistic` |
| `setKeyLock` / `setOnState` / `setWifiLock` | `type=setting`，对应整型字段 |

完整对照见 [README.md 指令对照表](./README.md#指令对照表)。

### 5.3 上行（设备 → 平台）

常见 `commandName` 与物模型映射（由脚本处理）：

| commandName | 平台侧 |
|-------------|--------|
| `device-timer-task` | 属性上报（current、power、voltage、energy 等） |
| `controller-event` | 事件 + 开关等属性 |
| `info-all` / `info-statistic` 等 | 属性上报 |

## 6. 验证清单

按顺序执行，便于定位问题环节：

1. **MQTT 连接**：设备在线；网关日志无认证失败。
2. **Topic 订阅**：网关已订阅 `/+/+/up`（见下文补丁 1）；用 MQTTX 向 `/gspm1b/{mac}/up` 发样例 JSON，平台有解码日志。
3. **透传脚本**：`GET /device/transparent-codec/gspm1b` 脚本为最新版；修改后建议重启网关或整服务。
4. **存储**：`dev_product.store_policy` 非 `none`；库中存在 `properties_gspm1b`；产品已 deploy。
5. **属性**：调用 `setTimerReport`（如 `timerEnable=1`，`timerInterval=15`），15s 内看到电流/功率等更新。
6. **下行**：调用 `powerControl`，在 Topic 上抓包确认为纯 JSON，且 `key` 为 `0`/`1` 整数。
7. **查询**：`queryInfo` / `queryStatistic` 后属性或事件有刷新。

## 7. 接入过程遇到的问题与处理

以下为本次实际踩坑与对应措施，便于后续型号复用或升级 JetLinks 时对照。

### 7.1 设备在线但上行无数据

**现象：** MQTT 已连接，属性始终为空。

**根因：** 官方协议包未将透传上行注册为 upstream route，MQTT 客户端网关未订阅设备上报 Topic。

**处理（本仓库补丁）：**  
`MqttClientDeviceGateway.ensureOfficialTransparentUpstreamSubscription()`  
在识别为 JetLinks 官方 MQTT 路由时，补充订阅 `/+/+/up`（不订阅 `/down`）。

**文件：**  
`jetlinks-components/network-component/mqtt-component/.../MqttClientDeviceGateway.java`

---

### 7.2 属性不入库 / 历史查询为空

**现象：** 实时日志有解码，数据库无记录。

**根因 A：** 产品 `store_policy = none`，数据不持久化。  
**处理：** 改为 `timescaledb-row`（或环境支持的策略）。

**根因 B：** 启动时 `DeviceProductDeployHandler` 在未将产品注册进 `ThingsRegistry` 的情况下调用 `registerMetadata`，`getTemplate` 失败被静默跳过，未创建 `properties_{productId}` 表。

**处理（本仓库补丁）：**  
启动流程中先 `deviceRegistry.register(product.toProductInfo())`，再 `doRegisterMetadata`。

**文件：**  
`jetlinks-manager/device-manager/.../DeviceProductDeployHandler.java`

**操作：** 修改存储策略后，对产品执行一次「激活/应用配置」或 `POST /device-product/gspm1b/deploy`。

---

### 7.3 功能调用无反应或 Topic  payload 异常

**现象 A：** 下行 Topic 上是整包 `DirectDeviceMessage` JSON，payload 为 base64。

**根因：** 官方 `TopicMessageCodec` 对 `DirectDeviceMessage` 下行序列化整条消息，而非原始字节。

**处理（本仓库补丁）：**  
`DirectPayloadDeviceMessageCodec` 包装官方编解码器：下行向 `/{productId}/{deviceId}/down` 发送原始 payload；上行 `/up` 解码前规范为官方 `/direct` 段。  
在 `RenameProtocolSupport.getMessageCodec` 中挂载该包装。

**文件：**  
`jetlinks-components/protocol-component/.../DirectPayloadDeviceMessageCodec.java`  
`jetlinks-components/protocol-component/.../RenameProtocolSupport.java`

**现象 B：** 脚本返回 `Map`，`EncodeContext.setPayload(Object)` 未序列化，payload 为空。

**处理：** `SimpleTransparentMessageCodec` 对 `Map` 使用 `ObjectMappers.toJsonString` 写入 payload。

**文件：**  
`jetlinks-manager/device-manager/.../SimpleTransparentMessageCodec.java`

---

### 7.4 下行 JSON 中 `key` 为 `1.0` 设备不识别

**现象：** Topic 上为 `{"type":"event","messageId":"...","key":1.0}`。

**根因：** JSR223 将脚本对象转为 Java `Map` 时数字常为 `Double`，Jackson 序列化为 `1.0`；设备要求整型 `0`/`1`。

**处理：**

1. 脚本：`toDevicePayload()` 对 `key` 等字段手写 JSON，使用 `parseInt`。
2. Java：`setPayload` 前 `normalizeJsonRoot` 将整数值浮点转为 `int`/`long`；字符串 payload 经 `scrubJsonWholeNumbers` 将 `:1.0` 纠正为 `:1`。

**文件：**  
`specs/gspm1b/transparent-codec.js`  
`SimpleTransparentMessageCodec.java`（同上）

---

### 7.5 界面无「数据解析」页签

**说明：** 社区版自带 `jetlinks-official-protocol` 可能未注册 `transparentCodec` UI 特性，与 `/direct` 透传能力并不矛盾。

**处理：** 使用 `POST /device/transparent-codec/{productId}` 保存脚本（见 [README.md](./README.md)）。

## 8. 本仓库代码改动索引

接入 GSPM1B 时建议在发行说明或 PR 中保留以下改动，升级上游时需做合并冲突检查：

| 模块 | 类 | 作用 |
|------|-----|------|
| mqtt-component | `MqttClientDeviceGateway` | 补充订阅 `/+/+/up` |
| device-manager | `DeviceProductDeployHandler` | 启动先注册产品再注册物模型存储 |
| device-manager | `SimpleTransparentMessageCodec` | Map→JSON、整型 JSON 规范化 |
| device-manager | `TransparentDeviceMessageConnector` | 透传编解码与下行日志（调试期） |
| protocol-component | `DirectPayloadDeviceMessageCodec` | 下行 `/down`、上行 `/up`→`/direct` 解码 |
| protocol-component | `TransparentMqttTopics` | Topic 约定常量 |
| protocol-component | `RenameProtocolSupport` | 挂载 DirectPayload 包装 |

**部署注意：** 修改 Java 代码后需重新编译并**重启** JetLinks；仅更新 `transparent-codec.js` 时可通过 API 热更新，但建议重启网关以确保加载一致。

## 9. 运维与扩展建议

1. **脚本版本**：将 `specs/gspm1b/transparent-codec.js` 纳入版本管理；变更后通过 API 重新提交并做一次 `powerControl` / 属性上报回归。
2. **多款型号**：若 `commandName` 一致可共用产品与脚本；差异大时在脚本内按型号分支或拆产品 ID。
3. **EMQX**：生产环境建议用规则引擎做 Topic 隔离与 ACL，规则模板见 [emqx-bridge.md](./emqx-bridge.md)。
4. **升级 JetLinks**：重点回归 `/up` 订阅、`/down` 下行、透传 API、物模型 deploy 四条路径；若上游已修复同类问题，可逐步移除本仓库补丁。
