## 4. 运行状态页 WebSocket 排障（本会话）

### 4.1 前端真实数据流（`jetlinks-ui-vue`）

核心文件：`device-manager-ui/.../Running/Property/index.vue`

1. `POST /dashboard/_multi`，`dimension: "history"` — 初始快照  
2. `wsClient.getWebSocket(...)`，topic：`/dashboard/device/{productId}/properties/realTime`  
3. 收到 `type: "result"` 后更新 `propertyValue`

DevTools **只见 history POST 属正常**，不能据此判断未订阅实时。

WS 全局连接在 `src/package.ts` → `initPackages()`：`ws://{host}{BASE_API}/messaging/{token}`。

### 4.2 现象与结论

| 现象 | 结论 |
|------|------|
| Network → WS 完全为空 | 全局 WS 未建立（token 时机 / 未 `initPackages`） |
| 仅有 `ping` / `pong` | WS 已连，尚未 `sub` 或 token 失效后只剩心跳 |
| Console `getWebSocket undefined ...` | 调试 log 误读；`undefined` 为微前端 `wsClient`，非失败 |
| 重启后需重新登录才刷新 | WS URL 含 token；过期后 HTTP 可能仍可用，实时推送失效 |
| 重登后 OK | ✅ 符合预期 |

### 4.3 运维提示

- 访问 UI 后确认 Console 有 `WebSocket connected`  
- 进入运行状态 Tab 后 WS Frames 应有 `sub` → `/dashboard/device/gspm1b/properties/realTime`  
- 设备上报时应有 `type: "result"`  
- token 过期后重登即可（不必改前端）
