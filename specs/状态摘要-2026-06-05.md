## 4. 今日关键问题与结论

### 4.1 协议 JAR 上传失败（`Connection refused`）

**现象：** `无法加载协议: finishConnect(..) failed: Connection refused: /192.168.0.4:3848`

**原因：** 上传后配置里 `location` 为 `http://{base-path}/file/...`；`AutoDownloadJarProtocolSupportLoader` 用 WebClient 自连下载。`base-path` 不可为 `127.0.0.1`（`ConfigVerificationService` 强制局域网 IP），但若本机进程访问 `192.168.0.4:3848` 失败则加载失败。

**处理：** 保证本机 `curl http://<局域网IP>:3848/system/config/base-path/verification` 成功；清理 `./data/protocols/` 失败缓存后重新上传。

### 4.2 功能调用界面超时（设备已执行）

**现象：**

```text
send device[c82b96f821e2] message complete
（约 10s 后）
cancel receive device[c82b96f821e2] message[2062723776656920576]
```

MQTT 可见下行 `/down` 与上行 `/up`（`source:command`、`messageId` 一致），设备行为正常。

**原因：** `MqttClientDeviceGateway` 解码时使用 `UnknownDeviceMqttClientSession`，`FromDeviceMessageContext.getDevice()` 为 **null**。旧版 `GemeOpenMqttMessageCodec` 直接 `Flux.empty()`，**未生成 `FunctionInvokeMessageReply`**，平台 `DefaultDeviceMessageSender` 默认 10s 超时。

**修复（仓库内）：** `device == null` 时从 Topic `/{productId}/{deviceId}/up` 解析并调用 `decodePayload`。

**待操作：** 重新 `mvn package` → 上传 JAR → 协议重新发布 → **禁用** 产品级透传脚本 → 再测功能调用；成功日志应出现 `receive device[...] message[...]`。

### 4.3 编码风格说明（会话结论）

| 模块 | 风格 |
|------|------|
| `gemeopen-protocol-core` | 纯 Java、同步；无 Reactor；便于单测 |
| `gemeopen-protocol-jetlinks` | 实现 `DeviceMessageCodec`；边界 `Flux`/`Mono`；编解码本体仍同步 |

与 JetLinks 常见模式一致：**SPI 响应式，协议算法同步**。

## 9. 运行状态页不实时刷新（本会话）

### 9.1 现象

- 设备在线，MQTT 可见上报，属性**已入库**。
- 设备详情 → **运行状态**：停留页签时数值不变；**离开再进入**可见新数据。
- 透传时代与换 `gemeopen-mqtt` 后均**未改前端**；用户 DevTools 仅见一条 `POST /dashboard/_multi`（`dimension: history`）。

### 9.2 前端机制（`jetlinks-ui-vue` / `device-manager-ui`）

文件：`src/modules/device-manager-ui/views/device/Instance/Detail/Running/Property/index.vue`

```text
进页 / 翻页
  → POST /dashboard/_multi  (dimension: history, history: 1)   ← 初始快照
  → wsClient.getWebSocket(
        topic: /dashboard/device/{productId}/properties/realTime,
        parameter: { deviceId, properties[], history: 1 }
     )                                                         ← 页内实时
  → 收到 type=result 后更新 propertyValue
```

- **不会**用 POST + `realTime`（后端 POST 处理器会过滤 realTime 维度）。
- **不会**用 HTTP EventSource 做该页（curl 可用的 SSE 是等价后端能力，非 UI 实现路径）。

### 9.3 后端已排除

`DevicePropertiesMeasurement.fromRealTime` 订阅：

`/device/{productId}/{deviceId}/message/property/report`

curl GET SSE（`measurement: properties`, `dimension: realTime`）可持续出数 → **协议 JAR 入库与 EventBus 发布正常**。

### 9.4 控制台日志（误报）

| 输出 | 说明 |
|------|------|
| `undefined 'ref'` | `console.log(tableRef.value,'ref')` 在 `watch immediate` 时 ref 未挂载 |
| `getWebSocket undefined instance-info-property-...` | `@jetlinks-web/core` 调试 log：`this.wsClient` 非微前端时为 undefined；长串为订阅 id |

### 9.5 下一步排查

1. Network → **WS**：`/api/messaging/{token}` 是否 101。
2. 是否有 `sub` → `/dashboard/device/gspm1b/properties/realTime`。
3. 设备上报时是否有 `result`，`payload.value.property` 有值。
4. 无 WS：查登录后 `initPackages()` 是否在 token 存在时执行。
